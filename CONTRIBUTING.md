# Contributing to SwitchboardIO

Thank you for your interest in contributing to SwitchboardIO! This project is built to be modular and extensible, and we welcome contributions of all kinds.

## How to Contribute

1.  **Pick an Issue**: Look for issues labeled `help wanted` or `good first issue`.
2.  **Fork & Clone**: Fork the repository and clone it locally.
3.  **Create a Branch**: Create a feature branch for your changes.
4.  **Implement & Test**: Make your changes and ensure everything works as expected.
5.  **Submit a PR**: Open a Pull Request with a clear description of your changes.

## Issue Labeling System

We use a specific labeling system to help contributors find the right tasks:

### Difficulty
*   `good first issue`: Simple tasks for newcomers (e.g., basic styling, mock providers).
*   `intermediate`: Requires understanding of the provider abstraction or storage patterns.
*   `advanced`: Complex architectural changes or deep integrations.

### Area
*   `area:frontend`: React components, CSS, UI/UX, and markdown rendering.
*   `area:backend`: API routes, LLM provider adapters, and storage implementations.
*   `area:dx`: Tooling, tests, documentation, and CI/CD.

### Type
*   `feature`: New functionality.
*   `bug`: Fixing something broken.
*   `enhancement`: Improving existing functionality.
*   `documentation`: Improving READMEs or adding guides.

### Status
*   `help wanted`: Open for anyone to take.
*   `in progress`: Someone is already working on it.
*   `needs discussion`: Needs more planning before implementation.
